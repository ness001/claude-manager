Claude Manager — Consolidated Design (Verified)

Complete component design with all verifier corrections integrated. 8 agents (4 proposers + 4 verifiers) aligned on this spec.

Key Corrections from Verifiers

  1. MCP configs live in ~/.claude.json, NOT settings.json. "Local" scope = per-project data in .claude.json under projects["path"].mcpServers.
  2. sessions-index.json is stale — 17/20 JSONL files missing from it. Must enumerate .jsonl files directly.
  3. PID files are deleted on session end — only active sessions have files in sessions/.
  4. Process is node.exe, not claude.exe. Must check CommandLine for claude-code/cli.js.
  5. PTY not in tauri-plugin-shell — need custom Rust plugin with portable-pty crate or ConPTY.
  6. Session names (slug) not indexed — appear deep in JSONL, only in 9/20 sessions.
  7. Plugin version can be 12-char git SHA, not always semver (e.g. a5bcdd7e58cd).
  8. Dual-write risk — must verify no PID file references a sessionId before resuming.
  9. Permission mode has 6 choices: acceptEdits, auto, bypassPermissions, default, dontAsk, plan.
  10. document-skills has NO plugin.json — metadata comes from marketplace registry only.

1.5 Terminal / Conversation View

Sessions started BY the app: Full xterm.js terminal via custom Rust PTY plugin (portable-pty crate). Tauri IPC bridges PTY to frontend (pty-data, pty-input, pty-resize events).
Alive sessions started externally: Read-only JSONL tail view with live updates. "Resume in Terminal" button opens OS terminal window running claude --resume.
Ended sessions: Read-only conversation viewer with virtual scrolling (@tanstack/react-virtual for 200+ message blocks). Jump-to-date navigation. Compact/microcompact boundaries as anchors.
Large file handling: Filter out progress lines (~80% of file) before rendering. Parse first 50 messages immediately, rest in Web Worker. Track byte offset for incremental reads on live sessions.

1.6 Data Discovery Strategy

DO NOT rely solely on sessions-index.json — it is a stale cache.

Correct approach:
1. Enumerate ~/.claude/projects/*/ directories to find all project slugs
2. For each project, glob *.jsonl files (each = one session)
3. Parse first ~10 lines of each JSONL for: sessionId, permissionMode, model, version, gitBranch
4. Cross-reference with ~/.claude/sessions/*.json PID files for alive status
5. Use sessions-index.json as a speed optimization (cache hit for summary, firstPrompt, messageCount)
6. Validate cache: if JSONL mtime > index mtime, re-parse that session
7. Store computed metadata in app SQLite for fast subsequent loads

3. MCP Servers Component

VERIFIER CORRECTION

MCP configs are stored in ~/.claude.json, NOT in ~/.claude/settings.json.
• User scope: .claude.json → $.mcpServers.<name>
• Local scope: .claude.json → $.projects["<path>"].mcpServers.<name> (per-project, private to user)
• Project scope: <project-root>/.mcp.json (shared, committed to git)
Project scope servers have a trust system: enabledMcpjsonServers / disabledMcpjsonServers arrays track approval.

7.5 Discovered Data Not in Original Design

The verifiers discovered additional data sources that enrich the app:

• tasks/ — Per-session task lists with status, dependencies. Natural dashboard widget or session detail tab.
• plans/ — Markdown implementation plans. Renderable in session detail.
• ide/*.lock — Connected IDE instances (VS Code) with workspace folders. Show as badges on IDE-originated sessions.
• history.jsonl — Full prompt history across all sessions. Enables searchable prompt recall.
• subagents/ — Sub-agent conversations per session (.jsonl + .meta.json). Show agent teams in session detail.
• file-history/ — File modification tracking per session. "Session impact" view.
• debug/ — Debug logs (some 100MB+). Log viewer with filtering.
• backups/ — Auto-backups of .claude.json with timestamps.

These are candidates for v2 features. The core spec focuses on Sessions, Plugins, MCP, Dashboard, Settings.
